## 0. 操作者（記入者）モデル【監査#1対応・新設】

共有アカウント案を既定とし、**「認証（Supabase Auth）」と「操作者（誰として記録・既読するか）」を別レイヤー**に分ける。個別アカウント案に裁定された場合は本節の操作者=Auth ユーザーに縮退（ピッカー廃止・照合ロジック流用）。

- **操作者ピッカー画面**: 職員一覧（staffスナップショット由来・かな絞込付き・各行 min-height 44px）。表示タイミング: ①初回起動 ②`cl_staffId` 照合失敗時 ③ヘッダの操作者チップをタップした明示切替時 ④再確認条件成立時。
- **再確認シート**: 起動時に保持 staff_id が有効なら「（職員名）として記録します［続ける／切り替える］」のワンタップ確認。毎回は煩雑なため、**日付が変わった or 最終操作から4時間経過**の場合のみ表示する案（頻度は承認時に1点確認）。誤帰属（別職員名義の記録・既読）は記録の信頼性を毀損するため、M-034（二重照合）の精神で明示確認を挟む。
- **保持**: `cl_staffId` に **staff_id 数値のみ**（氏名・かな等は一切保持しない）。起動時に Supabase 側 staff スナップショットとホワイトリスト照合し、不在・無効値・退職済みはピッカーへフォールバック（壊れた値で起動不能にしない）。
- **ヘッダ常時表示**: スティッキーヘッダ右に操作者チップ（氏名・タップで切替）。シフト交代時の切替導線を1タップに置く。
- **既読付与は明示操作のみ**: 本文展開タップ or カード内「既読にする」ボタン（44px）で `note_reads(note_id, staff_id)` を書く。**一覧レンダリングや自動スクロール到達では書かない**（multi-device-sync 原則9: 表示系から書き込まない。誤既読=未読喪失の防止）。一括既読は初版では設けない（誤タップで未読喪失＝破壊的操作に近いため。要望があれば確認ダイアログ付きで追補）。
- 「✓既読 5」タップで既読職員一覧をポップオーバー表示（職員名のみ・入居者情報を含まないため覗き見配慮の対象外）。
- 申し送りフォームの記入者欄は**現在の操作者を初期値**（変更可・ピッカー同一部品）。

## 0.5 入力解禁フラグ（並走期間の封鎖）【監査#2対応・新設】

- `app_settings` の入力解禁フラグ（切替日D or boolean。キー定義は Subagent 1 管轄）を起動時＋記録タブ表示時に**毎回取得**（「前提情報は毎回取り直す」規範。Realtime 購読があれば即時追従）。
- **封鎖中のUI**: 記録タブ・「＋申し送り」ショートカット・外出外泊入力は**隠さずディセーブル＋理由文**「現在はスプレッドシートで記録する期間です（アプリ入力の開始日は施設で決定します）」。タイムライン・検索・カルテは全機能有効（閲覧・検証専用モード）。
- **二重ガード**: UIの封鎖だけに依存せず、全書込関数の入口で共通ガード（フラグ再検証→不許可なら書込せずエラー表示）。**最終強制は RLS/DB 側**（Subagent 1 管轄）で、フロントは早期失敗と説明文を担当。
- importer の skip 計数（M-024計数式）・部分uniqueの衝突規則は Subagent 1/3 管轄のため本設計からは参照のみ。

## 3. 無限スクロール実装方式【#3反映】

- **フェッチ**: **初期=直近10日・追加=10日ずつ・RPC1発**に統一（要求原文「直近10日分」に整合。Subagent 1 のRPC定義に従う）。1チャンクの構成データは**7種**（①申し送り ②既読状態 ③バイタル ④食事・水分 ⑤外出・外泊 ⑥継続ピン ⑦日次取込状態）を1レスポンスで受ける。日付降順range条件のみ・全件ロード経路をコードに作らない。旧記述「3系列並列 or RPC1発」は撤回。
- **描画コスト遮断**: 日セクションに `content-visibility:auto; contain-intrinsic-size: auto 800px;` → 画面外の日はレイアウト・描画スキップ。末尾sentinel `<div>` を IntersectionObserver（rootMargin '600px'）で検知→次の10日を追加。
- **DOM上限**: 保持60日分。超過したら**古い側の日セクションをアンマウント**し、先頭に「これより新しい日を再読み込み」バーを置く（データはメモリキャッシュ保持・再表示は再マウントのみ）。60日×約80ノード≒5,000ノード以内（Lighthouse警告閾値未満）。
- **仮想スクロールライブラリ: 不採用を推奨**（変更なし）。根拠: ①可変高カード＋展開/折りたたみ＋sticky日付見出しは仮想化の高さ推定と相性が悪くカクつきの主因になる ②content-visibility＋日単位アンマウントで同目的を依存ゼロで達成 ③engineer-brain [73][74][81]。将来実測でfps不足の時のみ @tanstack/react-virtual を再検討。
- **フォールバック**: content-visibility 非対応環境でもDOM上限60日だけで成立する設計。施設iPadのSafariバージョンでの対応可否は**未検証**（Safari 18以降で対応・要実機確認）。
- **体感指標と測定**: 初期タイムライン描画 <1,000ms（再訪 <400ms）／スクロール60fps・dropped frames <5%／追加10日ロード <500ms。測定は合成データ1万件以上（M-026）で Chrome DevTools Performance＋React Profiler、実機iPadは Safari Web Inspector。数値は完了報告に実測添付（原則9）。

## 4. インクリメンタル検索UI

- デバウンス **250ms**＋**IME composition中は発火しない**（compositionend待ち。日本語入力で必須）。最低2文字（利用者名は1文字可＝33名メモリ内・かな/カナ/部分一致正規化でゼロレイテンシ）。
- 対象切替: セグメント「利用者名／本文／記入者」＋フィルタ行（期間プリセット: 10日/1M/3M/1Y/全期間・重要度・勤務帯・職種タグ）。本文検索の方式（pg_trgm等）は Subagent 1 管轄。
- 結果: 件数「〜n件」先頭表示・一致語 `<mark>`（bg:--c-accent-bg・下線併用=色だけ禁止）・結果行はタイムラインと同一カード部品（タップで該当日のタイムラインへ or カルテへ）。
- 3状態: ローディング=スケルトン3行＋「検索中…」／エラー=「検索できませんでした（通信エラー）。電波状態を確認して再試行してください」＋再試行ボタン／0件=「該当する記録がありません。期間を広げるか別の語をお試しください」＋「期間を全期間に広げる」ボタン。

## 5. 個人カルテビュー

- ヘッダ: 氏名（--fs-xl）・かな・居室・階。到達は明示操作のみ（一覧・タイムライン氏名タップ）＝覗き見配慮。
- 期間セグメント: 2週/1M/3M/6M/1Y（既定2週・cl_karteRange で復元）。
- **バイタル折れ線=自前SVG**（外部チャートライブラリ不使用を確定推奨・変更なし）: 縦積み4パネル（体温／血圧上下2線／脈／SpO2）、`viewBox` 幅100%・高さ160px相当。しきい値帯は半透明 `<rect>`（--c-warn-bg/--c-danger-bg）＋帯端にしきい値数値ラベル（色だけ禁止）。欠測日は線を切る（nullを補間しない＝「記録なし」の誤読防止）。データ点は透明44pxヒットrectでタップ→値ツールチップ。`role="img"`＋aria-label要約＋`<details>`内に同データの表。根拠: 必要なのは線・帯・点のみで、recharts等は+80KB超・トークン色/200%対応の制御が難しい（engineer-brain [73][8]）。
  - 2026-10-08 改定（代表指示）: 高さは画面の高さから決める（iPhone 1画面に1枚・広い画面に2枚・200〜360px。印刷は従来どおり160px・従来幅）。縦軸は記録の値に合わせて拡大し（指標ごとの最小の幅・区切りのよい目盛）、範囲外のしきい値は軸の端に「38.1↑」「35.5↓」と出して aria-label でも伝える。グラフの欄（バイタル・体重のグラフ・食事）だけ広い画面で最大 max-w-6xl まで広げ、文字の欄は max-w-2xl のまま。食事・水分の欄に「主食＋副食（1食あたりの日平均・低摂取6の線）」「水分量（ml/日）」のグラフを表の上に置く。計算は src/lib/chart.ts（tests/chart.test.mjs）。
- 食事・水分履歴表: 日付逆順・朝昼夕×主/副0〜10＋水分ml（tabular-nums）。低摂取セル▲+warn色、「外出」文字表示。外出・外泊の当日レコードがあれば行末に「外出」chipを併記（自動連動でなく併記【#6】）。
- 関連申し送り: タイムラインと同一カード部品を本人分フィルタで時系列表示（部品共有=変更増幅の防止 [2]）。

## 6. 入力UX

## 8. tokens.css × Tailwind 統合方針

- `src/styles/tokens.css` にトークン正本をコピーし index.css 冒頭で import。`index.html` に `data-ds="ops"`、`data-mode` は設定画面（ライト/ダーク/OS追従）でJS付替え。
- **tailwind.config を extend でなく置換**（kitchen-app は extend だが本アプリは直書き禁止を構造化）:
  - `theme.colors` = `{ bg:'var(--c-bg)', surface:'var(--c-surface)', ink:'var(--c-ink)', …danger-bg 等トークン全量 }` のみ → `text-slate-500` や `#333` 相当のクラスが**存在しなくなる**
  - `theme.fontSize` = fs-2xs〜fs-2xl のvarマップのみ／`spacing` = sp-1〜8のvarマップ＋`tap:'var(--tap-min)'`／`borderRadius` = r-sm/md/lg
- ダークモード: 全色がvar経由なので Tailwind `darkMode` 設定不要（data-mode切替だけで全画面追従）。
- 直書きの機械ガード: arbitrary value（`text-[14px]`・`bg-[#…]`）をCIで `grep -RnE '\[(#[0-9a-fA-F]|[0-9]+px)' src/` により検出しfail。hig-audit critical 0 と併走（サマリチップのヒット領域拡張も検証対象【#5】）。
- 200%文字: トークンがrem基準＋固定高さ禁止（min-heightのみ）で追従。reduced-motion はトークン側対応済み・アニメーションライブラリを入れない（CSS transitionのみ）。

- 重い順に並べ最大 8件。**入院中・外泊中の日（食事の status='hospital'、または外出外泊の期間に重なる日）は兆しを数えない**

### 10.5 排便の14日窓

- 排便は直近14日の窓で、排便の間隔と「最後の排便から ◯日」を出す（排便記録の端末側と同じ窓）。札に「直近14日」と書く

### 10.6 体重の基準日

- 1か月・3か月・6か月それぞれ、**期間の始点に最も近い過去の計測**を基準にして減少率を出す。その期間に基準の計測が無ければ null（「—」）で、兆しにしない

### 10.7 医療の欄の状態と文言

| 状態 | 表示する文言 |
|---|---|
| ok | 病歴・内服薬を出す。写しの日時（synced_at）が3日より古ければ「◯月◯日時点の写し」を添える |
| no_function | 病歴・内服薬の読む口がまだ用意されていません（管理者が共通 DB に 0037 を適用すると出ます） |
| no_shadow | 入居者マスタの写しがまだありません（管理者が入居者マスタを開くと1日1回写ります） |
| not_linked | マスタとの照合が済んでいません（source_id が空、または照合が needs_review の時。読みに行かない） |
| error | 読み込みの失敗（何が起きたか＋次にどうするか） |

- 状態の分類は `classifyMedicalState`、行の整え（文字／配列／null／オブジェクトを行の並びにし空行を捨てる）は `normalizeMedicalRow`（どちらも glance.ts）
- 読んだ値はメモリだけ。端末に保存しない

### 10.8 端末に残すもの（§9 の追加）

- `cl_glanceRange`（期間）・`cl_glanceSort`（見守りボードの並び）の2つだけ。既知値照合・未知は既定（`parseGlanceRange`・`parseGlanceSort`）。キー定数は glance.ts（`GLANCE_RANGE_KEY`・`GLANCE_SORT_KEY`。凍結の types.ts の LS には足さない）
- 氏名・id・医療の値・選んだ入居者は保存しない

### 10.9 開発用の見本

- `glance-preview.html`（ルート）＋`src/dev/glancePreview.tsx`。`npx vite` で開いて見るだけ（`vite build` の入口は index.html だけ＝公開物に入らない）
- 架空データだけ（人名・病名・薬剤名は「架空」を名乗る）。db・supabase・gasClient を import しない
- 端末に置くのは本物の画面と同じ `cl_glanceRange`（期間）・`cl_glanceSort`（並び）の2つだけ（§10.8 と同じ既知値照合。読み込み直しても期間・並びが残る）。役割・医療の欄の状態の切り替えは置かない
- 見本は favicon を取りに行かない（`<link rel="icon" href="data:,">`＝404 の console エラーを出さない）。`?check=1` の自動の確かめは描画の後に回して走らせる（effect の中で flushSync を呼ばない）
- 役割（field／office／admin）と医療の欄の状態（ok／no_function／no_shadow／not_linked）を切り替えて見る。`#board` で見守りボード、行を押すと見本の中のひと目ボード
- 確かめの段（runCheck）は画面の中と `window.__glanceCheck` に結果を出す（console に出さない）
- runCheck の8段（2026-10-29 の仮の合格ライン。`glance-preview.html?check=1` をヘッドレス Chrome で開くと自動で走り、`data-check-all="ok"` になる）:
  1. 兆しに「平熱+1.0℃以上」がある 2. 兆しに「水分8割未満」がある 3. 兆しに「体重1か月3%以上減」がある 4. 兆しが重い順・最大8件
  5. 医療の欄がどの役割（field／office／admin）にも出て、no_function／no_shadow／not_linked の文言が §10.7 どおり 6. 期間を切り替えても医療の欄を読み直さない
  7. 見守りボードが16名・入院中の行は数えない・未接続のマスは「—（カルテで確認）」・「変化の多い順」で並びが変わる 8. 幅1024以上でひと目ボードの画面全体が縦に動かず、変化の兆し・バイタル・温度板・食事水分排便・医療の欄・最新の体調変化の見出しがすべて画面の中に出る（外に出た区画の id を結果に出す）
- 見本の切り替え（役割・医療の欄）と「確かめる」は見出しの帯の上の1段にまとめる（別の段を足すと 1366×768 で下の区画が画面の外へ押し出される）
- 表示の部品は `src/components/glance/`（ひと目ボード＝`Glance*`・`VitalCards`・`TempBoard`・`IntakeCards`・`MedicalPanel`・`RecentChanges`。束ね役 `GlanceView` を画面と見本が共有）。見守りボードの部品は `board*`（`boardTable`・`boardCell`・`boardSortToggle`）
